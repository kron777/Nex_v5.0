# ADR-001 — Phase 0 Evidence and Causal Trace Approach

**Status:** DRAFT — not ratified  
**Date:** 2026-11-23  
**Repository baseline:** `6e6712bd4bde15ad2288f220cd4438b11622c93c`  
**Decision authority:** Founder Sign-Off > Frozen V2.1 Spec > Runtime Truth > Master Roadmap v3.0

## 1. Context

Master Roadmap v3.0 defines Phase 0 as a reality audit and end-to-end causal trace. It requires a repository/environment/test baseline, architecture crosswalk, specification reconciliation, and a minimal default-OFF read-only `InfluenceRecord` trace overlay.

The inspected repository has existing instrumentation, SQLite writers, Fountain event/crystallization records, a global workspace, a CoherenceGate and a separate Chat context-assembly path. The exact causal relationship between these mechanisms and subsequent output is not yet established.

The public `main` snapshot does not contain the required Phase 0 reports or a genuine causal trace sample. The deployed host and runtime are unavailable to this inspection.

The exact Frozen V2.1 specification and founder approval record have not been located in the available Library/repository search. Because Frozen V2.1 has higher authority than the roadmap, this ADR remains a draft and cannot settle any conflicting acceptance criterion.

## 2. Problem

NEX has multiple partially overlapping evidence sources: source code, tests, DB records, runtime logs, observation reports and descriptive architecture documents. These do not automatically establish the same thing.

A trace must distinguish:
- a mechanism being declared or present in source;
- a mechanism executing and emitting an event;
- a downstream component actually consuming that event;
- a downstream decision/output changing because of it;
- a measured behavioural improvement under a controlled comparison.

Without an ID-linked path, it is too easy to mistake a writer/table/HUD/log for a functioning cognitive feedback relationship.

## 3. Proposed decision — conditional on authority reconciliation

Prepare a minimal, read-only, default-OFF trace overlay using the existing NEX architecture as the source of truth. Do not introduce a parallel universal event store, new cognitive node, or new decision mechanism.

The roadmap's required flag name and default are:

```text
NEX5_TRACE_OVERLAY=0
```

The overlay's sole purpose is to observe and correlate causal influence. It must not gate, score, rank, block, veto, rewrite or otherwise influence NEX behaviour.

This is a design proposal only. No source implementation is authorised by this ADR.

## 4. Trace envelope — proposed minimum

An `InfluenceRecord` candidate should contain only the metadata required to join events and reconstruct ordering:

| Field | Purpose |
|---|---|
| `trace_id` | Identifies one top-level Fountain cycle or Chat turn |
| `record_id` | Unique identity for this observation |
| `parent_ids` | Immediate upstream observation IDs; empty only at a true root |
| `event_type` | Input, candidate, selection, gate, writer-delta or output observation |
| `producer` | Existing component that emitted the observed event |
| `consumer` | Existing component that received/used it, if proven |
| `source_ref` | Repository path and symbol for the observation point |
| `timestamp` | Monotonic ordering value plus wall-clock timestamp where available |
| `entity_ref` | Existing event/row/request identity where available |
| `outcome` | Actual observed selection/gate/write/output outcome, never an inferred one |
| `payload_digest` | Optional digest for comparison without retaining private content |
| `flag_state` | Whether the overlay was enabled for the captured run |
| `evidence_ref` | Exact log, test, snapshot or trace artifact reference |

This schema is not final. It must be reconciled with existing event IDs and persistence conventions before implementation.

Raw prompts, private conversation content, credentials and unrestricted environment values must not be copied into trace artifacts. Prefer stable IDs, bounded metadata and content digests. If a specific experiment requires raw content, it requires a separately approved, explicit retention and redaction plan.

### 4.1 Existing identity anchors discovered in source

The current source already provides persistence identities that should be reused rather than replaced:

- Fountain: `fountain_event_id`, returned by the existing Dynamic Writer after insertion into `fountain_events`.
- Chat: `session_id` and per-message row IDs returned by the conversations Writer. The current handler does not retain the message write return values as a turn-level chain.
- Writer: synchronous `write()` returns `cursor.lastrowid`; `write_many()` returns the corresponding row IDs.

A bounded source search of the Fountain generator/crystallizer, Chat handler and Writer found no existing general `trace_id` or `parent_ids` propagation. This does not prove no unrelated host/logging layer has a correlation ID.

The implementation should use the existing IDs as entity anchors, add only a top-level trace ID where needed, and carry parent links only across explicit calls/data dependencies. It must not infer parentage from timestamp proximity. The trace collector must not modify SQL, parameters, write ordering, prompt bytes, selection order, gate outcomes or outputs.

### 4.2 Existing logging and trace facilities reviewed

The current repository has logging facilities, but none provides the required safe, complete, ID-linked influence trace:

- `errors.py` keeps a 500-entry in-memory ring for all levels and a separate 500-entry WARNING+ ring. Both are bounded and can evict older records.
- Its durable `logs/errors.log` sink is a rotating text file (2 MiB, five backups) and deliberately accepts WARNING/ERROR/CRITICAL only. It is not a structured high-volume event stream and does not carry `trace_id` / `parent_ids`.
- `nex_config.setup_logging()` installs the central handler and configures namespace levels; it does not provide request/cycle correlation or causal parent links.
- Existing `/tmp/nex5_last_prompt.log`, `/tmp/nex5_last_chat_prompt.log`, `/tmp/nex5_deflection.log` and `/tmp/nex5_retrieval_history.log` are ad-hoc content logs. Some overwrite, some append; they do not provide causal IDs and include raw prompt/retrieval content. They are unsuitable as a new trace substrate and require a separate privacy/hygiene review.
- Existing Fountain and Chat SQLite IDs identify persisted entities, but do not propagate a top-level trace or parent chain through the complete path.

**Conclusion:** existing mechanisms cannot safely meet the required trace completeness, privacy and correlation properties without overloading the error channel or relying on raw-content debug logs. A separate external JSONL artifact is therefore a justified minimal candidate, not a second cognitive/event database. The path must be explicitly supplied, outside all NEX data directories, and the collector must remain default-OFF. This conclusion is source-level; the exact destination and retention still require approval.

## 5. Candidate observation paths

### 5.1 Fountain

The source inspection identifies these candidate points:

1. A Fountain-cycle trace root is created at the scheduler loop boundary, using the dynamic-state snapshot only as a payload digest.
2. Candidate generation is recorded after the thought is produced and before its persistence/gating path.
3. Global Workspace arbitration records winner/no-winner/disabled at the prompt focus-block boundary.
4. The generator records the existing `fountain_event_id` after the `fountain_events` insert.
5. The crystallizer records the quality result and the actual `CoherenceGate.check()` outcome when the gate is present.
6. Belief and `fountain_crystallizations` Writer-returned row IDs are recorded.
7. A speech-queue row ID and enqueue record ID are recorded when output is queued. A bounded, process-local hand-off lets the later consumer trace begin with the actual enqueue record ID in `parent_ids`; the consumer records suppression, synthesis, playback and failure outcomes. No ContextVar propagation or database column is assumed. If a queued row survives a process restart, the in-memory link is unavailable and the consumer starts an explicitly unlinked trace rather than inventing parentage.

The prototype uses a linear parent chain for observed sequential events. It does not invent multi-parent relationships where the source dependency has not been instrumented.

### 5.2 Chat

The source inspection identifies:

1. `POST /api/chat` input arrival is recorded after prompt validation.
2. User-message persistence records the Writer-returned message row ID.
3. Membrane/WorldModel retrieval is recorded with a payload digest.
4. Chat context assembly records the assembled context digest when the normal voice prompt path is used.
5. VoiceEngine query input/output or VoiceClient prompt/response boundaries are recorded. A returned VoiceEngine candidate is identified by a source-scoped `entity_ref` (`voice_candidate:<source>:<origin_id>`) with hit/miss outcome; candidate score and content remain digest-only under the current envelope.
6. The Chat gap-deflection gate records pass/deflect.
7. Gap-refusal and normal assistant-message writes record their Writer-returned row IDs; response completion closes the trace.

A Chat turn-level trace is source-instrumented, but no live turn has yet been captured.

The inspected Chat handler does not show the Fountain CoherenceGate being called on the reply path. The trace must record the actual Chat path; it must not fabricate a Gate event merely to force both pathways into the same diagram.

## 6. Read-only and default-OFF invariants

When disabled:

- no trace collector is constructed or invoked;
- no prompt, candidate, selection, gate decision, belief confidence, DB write or output changes;
- no extra DB reads or writes are introduced by the overlay;
- no runtime flag is changed by the collector;
- no event is injected into NEX;
- no Watcher/RDO observation is fed back into NEX.

When enabled in an approved isolated test:

- trace records are observational only;
- the collector cannot call NEX Writers to create trace rows;
- trace output is stored outside NEX cognitive databases in an explicitly approved test artifact location;
- failures in tracing cannot fail, delay or alter the cognitive path;
- sensitive content is excluded or redacted;
- the collector cannot alter process state or configuration.

The precise capture mechanism and artifact location require review against existing tracing/logging facilities before implementation. No new storage system should be introduced without demonstrating that existing mechanisms cannot meet the requirement.

### 7.2 Trace integrity

- Every non-root record references an existing parent.
- Parent links are acyclic within a single trace.
- Asynchronous consumer branches carry an explicit parent record ID when the process-local hand-off exists; ContextVar propagation is not assumed. A restart before consumption is an explicit, unlinked fallback case.
- Missing instrumentation is recorded as a gap, not filled by inference.
- Writer deltas refer to actual writes, not reconstructed guesses.
- One complete Fountain trace and one complete Chat trace are captured.
- The records can be independently reconstructed from source/test/runtime evidence.

### 7.3 Runtime capture

Only after host access, Frozen V2.1 reconciliation and required experiment approval:

- capture one complete Fountain cycle;
- capture one complete Chat turn;
- record exact code revision, flag state, model/backend, timestamps and relevant configuration fingerprint;
- preserve the resulting artifact and its hash.

No synthetic events may be injected into live NEX for this task.

## 8. Alternatives considered

| Alternative | Assessment |
|---|---|
| Treat DB tables/logs as a causal trace | Rejected: a write does not prove downstream consumption or influence |
| Build a second universal event store | Rejected at this stage: duplicates the substrate and exceeds the smallest justified scope |
| Instrument only the Fountain path | Incomplete: misses the distinct Chat pathway required by Phase 0 |
| Instrument all faculties immediately | Overbroad: first establish the two required complete end-to-end samples |
| Infer missing edges from architecture diagrams | Rejected: conceptual relationships are not causal evidence |
| Use an external observer to inject trace events into NEX | Rejected: violates the external Watcher/RDO boundary |

## 9. Consequences

Positive:
- Makes the gap between emission, consumption and actual influence inspectable.
- Supports later discrimination between missing capability, integration, calibration, temporal mismatch and instrumentation error.
- Reuses existing pathway identities and substrate rather than creating a parallel cognitive architecture.

Costs/risks:
- Instrumentation points may be distributed across large functions and asynchronous calls.
- Trace IDs may not exist at every current boundary.
- Capturing Writer deltas without changing write semantics requires careful design.
- Prompt and conversation metadata create privacy risks.
- A trace can still show correlation without proving behavioural improvement; L3 and L4 require their separate evidence criteria.

The next source increment must wire only demonstrable producer-to-consumer dependencies, then prove the complete Fountain and Chat paths.
