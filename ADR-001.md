# ADR-001 — Default-OFF InfluenceRecord causal-trace overlay

**Master Roadmap v3.0 Phase 0, deliverable M0.5.**

- **Status:** Accepted for the overlay mechanism · **Gate 0 (founder):** PENDING
- **Branch:** `claude/nex-v5-audit-review-53ouqv` · **Date:** audit at head `fb87e24`
- **Supersedes / superseded by:** none

---

## Context

Phase 0 requires an end-to-end causal trace: for a produced output (a Fountain
fire or a Chat turn), record the inputs that influenced it. The constraints are
strict and non-negotiable for a Phase-0 instrument:

- **Zero behavioural delta** — enabling or disabling the trace must not change any
  NEX output or any live-database state.
- **No live-state mutation** without authorisation — no new flags, no writes to the
  six substrate DBs, no runtime changes.
- **Runtime evidence stays UNKNOWN** until a founder-authorised live run produces it.
- **Optimal Functional Tension** — minimal mechanism, reuse before build, no new
  architecture.
- The governing Roadmap v3.0 PDF defining M0.5's exact fields is **not in the
  workspace**, so field-level specifics must be flagged UNRESOLVED, not invented.

## Decision

Introduce one cross-cutting module, **`influence_record.py`** at repo root
(matching the existing top-level cross-cutting-module convention, e.g.
`errors.py` — not a new package or architectural layer), providing:

1. An **`InfluenceTracer`** whose `record_fountain_fire(...)` / `record_chat_turn(...)`
   methods are **no-ops that return `None`** unless `NEX5_INFLUENCE_TRACE` is truthy
   (default unset ⇒ OFF).
2. **Side-channel-only** persistence: when enabled, append exactly one JSONL line
   to a dedicated file (`NEX5_INFLUENCE_TRACE_PATH`, default
   `logs/influence_trace.jsonl`, git-ignored) — **never** a substrate DB.
3. **No new reads:** the producer seam passes values already in scope; the tracer
   never traverses readers or calls back into the system, and never mutates an
   observed value.
4. **Fail-safe:** any internal error is swallowed; the traced path cannot break.
5. An **L0–L4 evidence ladder** reusing the Watcher `evidence_class` vocabulary,
   asserting **L4 only** under `NEX5_INFLUENCE_TRACE_CONTEXT=runtime`.

Integration is **two guarded one-call seams**, both skipping all work when the
flag is off:
- `theory_x/stage6_fountain/__init__.py` — after `generator.generate(...)`.
- `gui/server.py:2180` — after the reply is finalised, before `return jsonify(...)`.

## Alternatives considered

- **Hook inside `FountainGenerator.generate()` / `_assemble_chat_blocks()`** for
  belief-/block-level attribution. Rejected for this increment: invasive edits to a
  1,356-line generator and a ~1,000-line chat handler carry real regression risk and
  exceed minimal sufficiency. Recorded instead as `L0/UNKNOWN` in `unresolved`, and
  listed as outstanding in the crosswalk.
- **Write the trace into a new substrate table.** Rejected: that is live-state
  mutation and couples the overlay to the DBs the audit is meant to observe neutrally.
- **A new `instrument/` package.** Rejected as "inventing a module/architecture"; a
  single top-level file fits the existing convention.

## Consequences

**Positive.** Reversible, inert by default, provable zero-delta, reusable from any
producer, reconcilable with the Watcher ladder.

**Zero-delta evidence.**
- `tests/test_influence_record.py` (16 tests): faithful off-vs-on seam harnesses
  assert the produced output **and** the recorded DB writes are byte-identical
  off vs on (`test_*_seam_output_and_db_identical_off_vs_on`); the overlay does not
  mutate observed values; the sink is never a substrate DB; default is OFF.
- The real seam edits are inert with the flag unset, so the **existing suite is
  unchanged** — the regression evidence for the real integration.

**Negative / limits.**
- Coarse causal granularity (seam-level inputs only); finer attribution is deferred.
- **Live L4 capture is UNKNOWN** here (needs the running NEX + founder authorisation).
- `logs/influence_trace.jsonl` can grow unbounded when enabled; rotation/retention is
  a follow-up (not needed while default-OFF).

## Compliance with the directive

No new phase/architecture; existing conventions reused; no live state/flag/DB/runtime
altered; runtime evidence kept UNKNOWN; default-OFF with verified zero delta; frozen
baselines untouched. **Gate 0 approval is required before any Phase-1 behavioural
change and is not assumed.**
