# ADR-001 — Phase 0 causal trace overlay
## Default-off, side-channel, parent-linked evidence

- **Status:** Provisional implementation decision; candidate code is PR #151 and remains subject to exact-head CI and founder review.
- **Roadmap:** Master Technical, Research & Commercialization Roadmap v3.0, Phase 0 M0.5.
- **Evidence snapshot:** main at 49b1d6c0b247b5694259e1225d077fc60e5c3706; implementation candidate is separately maintained in PR #151.
- **Gate 0:** OPEN. This ADR is not founder sign-off and does not authorise Phase 1.

## Context

M0.5 requires an end-to-end causal trace for one Fountain cycle and one Chat turn. The required relationships include input arrival, candidate generation, salience/workspace selection, Gate outcome, SQLite writer delta and output. The trace must be reversible/default-off and must not mutate prompts, belief confidence or selection order.

The existing repository already contains several distinct observability mechanisms, including prompt-block manifests, retrieval logs, gate decisions, provenance snapshots and subsystem-specific JSONL logs. A second cognitive/event database or a new universal runtime store would duplicate existing substrate responsibilities and alter the state being audited.

A prior continuity-branch overlay used NEX5_INFLUENCE_TRACE and recorded only coarse producer seams. It did not meet the roadmap's NEX5_TRACE_OVERLAY flag and parent-linked stage coverage. It is a historical design reference, not the current M0.5 implementation.

## Decision

Implement one cross-cutting, default-off Python module, influence_trace.py, using the existing repository's cross-cutting-module convention. Its proposed contract is:

1. **Default OFF.** NEX5_TRACE_OVERLAY is unset/0 by default. The Chat and Fountain paths retain their pre-overlay call signatures and behavior when no trace context exists.
2. **Sidecar only.** When enabled, events append to a dedicated JSONL sidecar, default logs/nex_causal_trace.jsonl. The trace layer refuses non-JSONL destinations, symlinks and paths that alias configured substrate databases; it fails closed if path safety cannot be established.
3. **Parent-linked lineage.** Each event carries trace_id, event_id, parent_ids, sequence, producer, stage and event type.
4. **No new source reads.** Hooks receive values already available at the producer seam. The collector does not query a Reader, open a database for evidence collection or re-run selection/scoring.
5. **Privacy by default.** Text-bearing values are reduced to SHA-256 digests and lengths. Unknown free-form metadata strings are hashed; only bounded categorical labels and defined identifiers remain readable.
6. **Fail-safe.** Instrumentation errors are swallowed by the collector and do not replace a producer's decision or output.
7. **Evidence discipline.** Fixture/CI traces are L3. L4 is only emitted when an explicitly authorised host capture sets NEX5_TRACE_OVERLAY_CONTEXT=runtime. No live context is enabled by this work.
8. **No cross-database atomicity claim.** Writer.write commits a statement in one database; write_many is atomic within one database only. A Fountain cycle may commit separate rows to sense.db, dynamic.db and beliefs.db. The trace records those as ordered deltas, not as a single transaction.

## Integrated producer/consumer seams in the candidate

- Chat input, session/user/assistant message writes, Membrane route and existing retrieval result, fallback retrieval, workspace selection, assembled prompt, tool outcome, VoiceEngine stored candidate, VoiceClient output/retry and final sanitized reply.
- VoiceEngine candidate pool, score winner/threshold decision and existing throw_net_triggers write.
- Fountain readiness, retrieved belief IDs/source kinds, retrieval activation updates, existing workspace winner, retrieval/prompt manifests, prompt hashes, model/reconcile/retry outputs, output filters, quality outcome, Coherence Gate outcome, sense/dynamic/belief writes and optional speech-queue decision.
- Fountain substrate-voice, quiescent, stillness and voice-fallback paths are represented as distinct event types; they are not all treated as fresh model generation.
- Chat crystallization Gate is recorded as NOT_APPLICABLE because a Chat reply is not itself a belief write.

## Alternatives considered

### Reuse only the old coarse InfluenceRecord seam

Rejected as insufficient for M0.5. It used another flag and had unresolved candidate/workspace/gate/writer stage coverage. Reconciliation against the actual roadmap made the missing stages explicit.

### Create a new SQLite event store

Rejected. It would add schema/state and couple the audit to the live substrate it is intended to observe. It could also introduce new writer contention and cross-database semantics.

### Write trace events into the six substrate databases

Rejected. That would mutate the system under observation and invalidate the zero-delta requirement.

### Query Readers from inside the trace collector

Rejected. New reads can change timing/cost and create a second retrieval surface. Producer call sites must pass the candidate IDs and metadata already in scope.

## Evidence and limitations

- The repository CI sandbox is unprivileged, read-only, offline and uses disposable test data. The probe has passed in previous runs.
- A prior completed intermediate candidate run found 2,475 passed, 7 skipped and 5 failed. Those five failures were test-fixture mistakes in tests/test_influence_trace.py and were corrected on the candidate branch; they are not mainline failures.
- The current candidate includes paired full FountainGenerator.generate() OFF/ON and full Chat-route OFF/ON fixture replays. The Fountain pair compares model requests, retrieval manifests, workspace winners, beliefs/confidences, Fountain events, momentum state and table counts. The Chat pair compares response, model request, SQL read sequence, messages/sessions and table counts.
- The trace records direct SQLite commit events separately from Writer deltas, including recursion_attrib and momentum writes. This preserves the actual transaction boundary instead of pretending these direct connections obey the one-pen Writer contract.
- The exact current PR #151 head is in the disposable CI workflow; its full-suite, sandbox and mind-map results have not yet completed. M0.5 is not validated until that exact-head run is green and the fixture outputs have been reviewed.
- NEX_CAUSAL_TRACE_SAMPLE.json contains synthetic L3 fixture examples only. It is not evidence of a live Fountain cycle or live Chat turn.
- L4 runtime evidence remains UNKNOWN until an authorised, provenance-bearing host capture is performed.

## Consequences

Positive:
- Reversible observability without a new substrate DB or schema.
- Explicit candidate and writer lineage for future backward audits.
- Privacy and path safety are enforced centrally rather than relying solely on each call site.

Limits:
- Trace completeness is bounded by instrumented seams. Uninstrumented direct SQL writes and optional branches must remain explicit gaps.
- Fountain's recursion_attrib and momentum helpers currently write directly through substrate.connect(), outside the one-pen Writer contract. They should be traced as direct SQLite commits, not misrepresented as Writer deltas; any remediation requires a separate bounded change.
- Sidecar retention/rotation is not yet specified. The feature is default-off; if enabled for longer collection, retention must be bounded before a sustained soak.
- The trace identifies software lineage, not subjective experience, cognition quality or consciousness.
