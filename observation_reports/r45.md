R44 §C.1 asserted the damper was satisfied because `apply_decay` reads `belief_boost`, the same table `apply_boost` writes. **That check was correct and insufficient**, and the gap is worth naming precisely because the brief's damper rule is going to be applied again.

**But existence is not sufficiency. The rate is what matters, and I never checked it:**

| | |
|---|---|
| boost 1.40 → `NEUTRAL_THRESHOLD` 1.05 | 0.35 of decay to clear |
| `DECAY_RATE_PER_DAY` | 0.02 → **17.5 days to clear one boost** |

**The lesson, stated so the damper rule can absorb it — REASONED:** a damper must be checked for **rate adequacy against inflow**, not merely for existence and table-correctness. R44's rule caught Designs 3 and 4 (accumulators with no damper at all) but waved through Design 1, where the damper exists, reads the right table, and is still outpaced ~17.5:1. **I propose the damper rule gain a second clause: name the damper, confirm it reads the same table, *and* show its clearance rate exceeds the mechanism's production rate.**

## C. The offline prediction, run anyway — because it is the falsifier

The brief asked for a 24 h prediction. Producing it is what quantifies the harm, so it is here rather than dropped.

**C.1 — `belief_boost` 24 h after activation:** ~**13 rows** at 24 h, climbing to a steady state of ~**226** over 17.5 days. Values 1.35–1.42 (the empirical range recorded in `boost.py`), decaying 0.02/day.

**C.2 — does it change *which* beliefs are retrieved, or only their order?** **Which.** `_retrieve_context_beliefs` oversamples `own_n × len(_OWN_CONTENT_SOURCES)` and then applies per-source and per-branch caps. A boost of 1.40 adds `3.5 days × 0.40 = 1.4 days` to the sort key, so a boosted synergized belief displaces any unboosted belief created within the last 1.4 days **out of the oversample entirely** — it is not reordering a fixed set, it is changing set membership before the caps run. That is precisely what `b1a6165` describes: *"the oversample itself was dominated by future-projected synergized so sense never got enough representation."*

**C.3 — pre-registered falsifier, for the record:** had this shipped, failure would read as `belief_boost` empty after 24 h (reconnection dead) **or** row count exceeding ~40 at 24 h / ~250 at steady state (decay not keeping up). **The steady-state figure is already above that second threshold by construction, which is another way of saying the design fails its own falsifier before it runs.**
