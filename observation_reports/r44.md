### A.3 The seam

**`_retrieve_context_beliefs`, `generator.py:1907`, called once at `generator.py:2169`.** This is R6's "one flat recency query". Its ordering clause is:

```sql
ORDER BY (b.created_at + (COALESCE(bb.boost_value, 1.0) - 1.0) * ?) DESC LIMIT ?
```

**The seam is that `ORDER BY`, and it already has an extension point**: `belief_boost` is joined in and contributes an additive time-bonus. A graph-derived or tier-derived term would plug in as a second additive term in exactly the same place, with exactly the same shape. **No new plumbing is required to give beliefs influence — the socket exists.** §C explains why it is currently carrying zero.

A second seam exists for edge-traversal specifically: `_fire_focal` is bound at `generator.py:1340` (per R29's note) and is the natural anchor for "traverse outward from the current focal item".

## C. Beliefs' causal power over the fountain

### C.0 The finding that reframes this section — OBSERVED

**The damped belief-influence channel already exists, is already wired into the retrieval `ORDER BY`, and is carrying zero rows.**


The causal chain, traced end to end:

| step | state |
|---|---|
| synergizer produces children | **ALIVE** — `synergizer_log` 5,722 rows, last **0.0 d ago** |
| `DiversityLoop.grade_synergy()` grades them and boosts | **ORPHANED — no caller anywhere in the codebase** |
| `collision_grades` accumulates | **STOPPED 2026-05-14 — 87 days ago** |
| `belief_boost` holds boosts | **0 rows** (`apply_decay` removed the last of them) |
| `boost_value` in `_retrieve_context_beliefs` | **always 1.0 → the term contributes exactly nothing** |

`grade_synergy`'s own docstring says *"Called from the synergizer after a new belief is inserted."* It is not. `_synergizer_loop` (`stage3_world_model/__init__.py:199`) calls `state.synergizer.synthesize()` and never touches the diversity loop. **The two halves of the mechanism were never connected**, or were disconnected on 2026-05-14.

Historically it worked: 212 of 893 collision grades exceeded `BOOST_THRESHOLD = 0.35`.

**So the honest answer to "how could a belief gain influence over the fountain" is: it already can, and the wire is cut.**

### C.1–C.2 Design candidates, each with its damper named

The brief's constraint is non-optional: **every design must name its damper, and the damper must read the same table the mechanism writes.** Two of the four candidates below fail that test and are flagged incomplete rather than dropped.

---

**DESIGN 1 — Reconnect `grade_synergy` to the synergizer.** ✅ **damper satisfied**

- **Mechanism:** call `diversity_loop.grade_synergy(child_id, a, b)` after the synergizer inserts a child. Writes `belief_boost`.
- **DAMPER:** `boost.apply_decay()`, called from `diversity/consolidation.py:50`. It reads **`belief_boost`** — **the same table `apply_boost` writes** — decays every row by `DECAY_RATE_PER_DAY = 0.02`, and **deletes** rows below `NEUTRAL_THRESHOLD = 1.05`. Boost must be re-earned.
- **Why the damper is credible:** `boost.py` documents surviving this exact bug class twice. The original multiplicative formula produced *"a ~22-year time-shift per boost — a permanent retrieval lock rather than a learning gradient"*, and the additive coefficient was *"halved 2026-05-13: 7 days → 3.5 days to break Mechanism B retrieval crowding"*. The bound is empirically calibrated: at max observed boost the belief looks ~1.4 days newer than it is.
- **Risk: LOWEST.** Single reversible variable — one call site, revertible by deleting one line. Does **not** touch `generator.py` or `crystallizer.py`. The retrieval side is already deployed and unchanged.

---

**DESIGN 2 — Edge-traversal from the focal item.** ✅ **damper satisfiable, and it uses the dead column**

- **Mechanism:** from the fire's focal belief, traverse ≤1 hop over `supports`/`refines`/`opposes` (890 edges, the semantically meaningful ones), fan-out capped, and prepend N neighbours as retrieval candidates.
- **DAMPER:** **`last_traversed_at`** — the column that has been NULL on all 135,733 rows since inception. Set it on traverse; exclude edges traversed within a refractory window. The damper reads **`belief_edges`** — **the same table the traversal marks.** This gives the column its first purpose and makes repeat-traversal self-limiting.
- **Additional bound required:** hard fan-out cap (max out-degree is **630**) and graceful fallback for the **31.5%** of beliefs with no edges.
- **Risk: MEDIUM.** Touches `generator.py`'s retrieval path — cannot ship while C2 is live. Needs the edge-quality filter from A.4.

---

**DESIGN 3 — Tier-weighted retrieval.** ⚠️ **INCOMPLETE — no damper exists**

- **Mechanism:** add a tier term to the `ORDER BY` so higher-tier beliefs surface more.
- **DAMPER: NONE AVAILABLE, and this is disqualifying.** Tier is **monotonically non-decreasing** — beliefs are promoted and (apart from tier 8 retirement) never demoted. A tier weight therefore has no natural decay: a belief that reaches T6 outranks newer content **permanently**. That is precisely the "permanent retrieval lock" `boost.py` was rewritten to escape.
- **What would fix it:** either a demotion path writing the same `tier` column, or convert tier into a *bounded time-bonus* like boost — at which point it is Design 1 with a different grade source.
- **FLAGGED INCOMPLETE. Not recommended in this form.**

---

**DESIGN 4 — `confidence` / `reinforce_count` as sampling bias.** ⚠️ **INCOMPLETE — no damper exists**

- **Mechanism:** bias retrieval toward high-confidence or often-reinforced beliefs.
- **DAMPER: NONE.** Both quantities are accumulators that only rise on the paths that write them. Worse, this closes a **positive loop**: retrieved → reinforced → higher confidence → more likely retrieved. **This is structurally the R5 bug** — an amplifier with no opposing term.
- **What would fix it:** a decay on `confidence` written by the same path that reads it, which does not currently exist.
- **FLAGGED INCOMPLETE. Do not build.**
