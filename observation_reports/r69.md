## B2 — did a prior fix reduce it? **No — volume rose ~4×.** — OBSERVED

The fix that targeted *this exact template* is **`cf99584` (2026-07-05)**, which added a
burst-throttle: *"these questions only open if the identical title hasn't opened in the
last 24h."* (Not R27's gerund gate — that addressed single-word `Signal: investigate X`
problems, a different template.)

| week | branches active | template opened |
|---|---|---|
| W23–W27 (pre-fix) | 3–5 | 8 · 10 · 7 · 6 · 4 |
| **W28–W32 (post-fix)** | **8–10** | **17 · 24 · 26 · 25 · 24** |

**The throttle works exactly as written and aggregate volume still tripled.** Minimum
gap between identical titles is pinned at **24.00 h** for 11 of 13 titles (24.0008,
24.0088, 24.005, 24.010…) — that precision is the throttle. But the throttle caps
*per title*, so total = active branch count. **Branch count roughly doubled (4→8-10),
so total rose with it.** The fix converted "many per title" into "one per title per day
across a growing branch set".

**Throttle leak — OBSERVED:** 3 of 149 repeat-openings are under 24 h — `systems` at
**3.03 h** and `emerging_tech` at **12.30 h**. **2.0% leak rate.** Small, real, not
diagnosed here.

# C. `membrane: —`

## C1/C2 — producer→consumer trace — OBSERVED

**There is no producer. The dash is the hardcoded HTML default.**

```html
gui/templates/index.html:267
<span class="sb-seg" id="sb-membrane">membrane: <span class="mem-inside">—</span></span>
```

The only writer is inside `sendChat()`:

```js
gui/static/app.js:579-583   // Update membrane side display optimistically
const isSelf = /\b(you|your|yourself|feel|...|do you)\b/i.test(prompt);
memEl.textContent = isSelf ? "INSIDE" : "OUTSIDE";
```

So the field is populated **only when the operator sends a chat message**, by a
**client-side regex on the operator's own prompt**. Until then it shows its static
default. `membrane: —` means *no chat message has been sent this page-session* — nothing
more.

**This is NOT the `mem_percent`/`memory_percent`/thermal/load class.** Those were
producer-emits-X / consumer-reads-Y key mismatches. Here no server value is requested for
this element at all.

*(Separately, `app.js:347` `setDot("ms-mem2", data.membrane)` is a different widget — a
subsystem status dot — and does read a server value. It is not the bottom-bar readout.)*

## C3 — verdict

**DISPLAY ARTIFACT — benign, working as written.**

**One thing worth flagging, not fixing:** the label says `membrane`, and the server does
expose `/api/membrane/classify`, but the bar shows a **client-side regex guess about the
operator's prompt**, not NEX's membrane classification. Reading it as NEX's INSIDE/OUTSIDE
judgement would be a misreading. Naming/semantics issue, not a data defect.
