## D. The verdict

### D.1 — **NO. Not worth shipping at 3B.** — OBSERVED + REASONED

Net admission through the real gates is **+0.0353, CI spanning zero**. The primary pre-registered endpoint is null. There is a real benefit and a real harm and they cancel. **Shipping this would trade one gate for another and change nothing that reaches the corpus.**

**One honest caveat that cuts against my own null, and I will not bury it: the primary endpoint was at ceiling.** Recency `on_subject` was already **0.9599** overall and **0.9905** for EXPLAIN — there was ~4 points of headroom, and 1 point for EXPLAIN. **A metric that saturated cannot demonstrate improvement, so the `on_subject` null is weak evidence, not strong.** Where there *was* headroom — engagement failure at 0.44 — the effect was significant and favourable. **Choosing `on_subject` as the primary endpoint (R52 §D, my own pre-registration) was a mistake, and the decisive run is what exposed it.**

### D.2 — Retrieval or capacity? **Neither. It is a gate.** — REASONED from OBSERVED

R55 leaned toward capacity on two signals. The full run overturns that:

- **The model demonstrably conditions on the priors.** Engagement-failure fell **6.1 pp**, significantly. A model ignoring its context does not do that.
- **Dose-response exists, weakly, and only where there is headroom.** True dose (extra relevant priors delivered, of 9; mean **+8.10**): r(dose, Δengagement gain) = **+0.0695**, and by tertile the top third shows **+0.2537** engagement gain against **−0.0526** for the bottom. r(dose, Δ`on_subject`) = **−0.0253** — flat, as expected against a ceiling.
- **`novelty_F2` is pinned at 0.999 in both arms** — R55 read this as a capacity hint. With engagement moving, the better reading is that F2 is saturated as a *metric*, not that the model is inert.

**So the answer to the question behind the question — would a larger voice model change this? Not obviously, and that is the useful finding.** The 3B model used the better context; what stopped the benefit reaching the corpus was a **600-character threshold** in one mode. **That is a gate-tuning problem, and a bigger model would plausibly make it worse, since larger models write longer.** Before spending on model capacity, the cheap experiment is the length interaction — and the harness to run it already exists.

### D.3/D.4 — what follows, without manufacturing a follow-up

**Relevance retrieval alone: not shippable.** Stated plainly.

**The paired change R55 said could not yet be designed can now be scoped**, because C.2 localises the harm: it is EXPLAIN, and it is proximity to the 600-char ceiling — not prior length, so truncating priors would not work. A relevance + EXPLAIN-length-control variant is a *legitimate* next experiment, not an invented one. **But it is a second experiment**, it needs its own offline replay through the same harness, and it stays behind the register refit (~08-23) because maxDF\* is its tripwire. **I am not proposing to build it this round and I would not ship it without that replay.**

## E. The riders — both assessed, **both deferred**

**E.1 `pipeline_events` index — do NOT add it.** — OBSERVED

```
pipeline_events   28,206,791 rows, 245,084/day
table + indexes   2.28 GB = 48.4% of dynamic.db (4.39 GB on disk)
query plan        SEARCH ... USING INDEX idx_pipeline_branch  +  USE TEMP B-TREE FOR ORDER BY
rows sorted per call, 'systems' branch: 8,460,511 -> to return 10
```

An index on `(branch_id, magnitude, ts)` would remove the temp b-tree. **But it would add ~1 GB to the largest table in the system to accelerate a consumer that has produced 13 beliefs in the system's lifetime, last on 2026-07-13** — and it would make the reaper that is actually needed more expensive to run later. **The right fix is a reaper with a reader census (the R38 §C5 / R39 pattern), which needs its own round.** Deferred, not skipped.

**E.2 Drive-input removal — do NOT bundle it.** — OBSERVED + REASONED

Both inputs re-measured during the stop at **exactly 0.0000**, so R54's "form (a) is a literal no-op" holds. **The round is right that the replay could not have been contaminated** — it ran offline against a stopped fountain with its own prompts, and I confirmed that by inspection in §A.3. **But the fire path can be contaminated, and that is the reason to hold.** Bundling a prompt-writing change would have forfeited the byte-identical fire path across this restart — the property that keeps the pre/post fire series comparable — **for a change measured at exactly zero.** Its own trivial round, in form (a).
